# Content architecture v1.1

Approved design: all modules optional except puzzle controller and save system. Stable IDs; no fixed counts. Ten JSON Schema draft 2020-12 record definitions in engine/schemas. Game content paths are relative to game.json; each collection is an array of records. Empty collections valid during foundation. Nested condition, mechanic, sender, presentation and navigation contracts are intentionally provisional until their controllers are implemented.

Story chains contain zero or more ordered opening and closing journal IDs surrounding one eligible first-time puzzle completion. All applicable journals unlock even if skipped. Abandoned openings persist; next puzzle uses current chain. Explicit archiveAssignment determines character slots, not journal authors or counts. Journal blocks are ordered multimedia. Inventory remains collected after use. Multiple transmissions per target, one active per target; optional clues recycle via “Show me another clue”, with first-use and persistent explanation. Achievements automatically awarded once. Skin inheritance: default, adventure, module, packet override; bespoke narrative presentation allowed.

Task 5: load collections and validate schemas, references, uniqueness, sequence, mechanic contracts and module compatibility. No runtime validation in Task 4. Client-side solutions are inspectable. No final adventure content authored.

## Opening sequence (v1.1)
Ordered opening screen references, individual screen packets, default studio presentation with adventure overrides, optional sponsor links, manual title advance, always-skippable cinematics with once-only narrative grants. Access and tutorial completion are engine gates, not skin choices. Tutorial steps reference ordinary puzzles or instruction screens; enabled tutorial is mandatory, ordinary puzzle completion counts and story/rewards apply. Resume completed steps, reset unfinished attempts. Cold launch returns to title; waking resumes current screen. Established onboarded QR sessions route directly. Initial QR policy configurable: require-rescan, auto-launch, ignore. NatGeo requires rescan with one-time optional prompt after onboarding, opens archive on latest tile recipient, opens recipient after puzzle, remembers last viewed character on manual archive access, uses configured default if no tiles. Continue restores last meaningful non-puzzle screen. Save opening progress, grants, tutorial progress, initial QR and prompt status, last screen and character pointers. Task 5 validates screen and puzzle references; runtime lifecycle, default studio assets, payment, recovery and sponsor analytics remain unimplemented. Home Edition opening collection is empty pending content design.
